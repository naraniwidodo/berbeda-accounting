1 · The problem

Books a founder cannot hand over

Ber.be.da paints people’s stories onto worn out fashion items, and employs local artists in Bantul, Indonesia. 9,000 followers on TikTok, 4,000 on Instagram.

  • Accounting for a service business is its own thing. The chart of accounts differs from one studio to the next, so the work is hard to hand over and off the shelf software is almost useless without paid customisation.
  • It eats the week. Record every entry, check that assets equal liabilities plus equity, decide how to treat the accrual.
  • Then the analysis. Ratios by hand are easy to get wrong.

2 · What is new

Built for one industry, not for everyone

The chart of accounts, the posting rules and the sales process all come from how a custom painting studio really works. You cannot buy this system anywhere.

Etsy templates

Cheap, but the owner still has to customise every account, usually with a consultant.

Hire an accountant

Easy and expensive, and you still have to explain the business first.

Software & spreadsheets

Mature, but a spreadsheet cannot enforce an accounting rule. That is how a book goes out of balance.

A general chatbot

Explains accounting well, but you still journal by hand and still have to check it.

The difference: the posting rules live in code, not in the model, so they cannot change by accident. The model is used only where judgement is needed.

3 · How it works

One agent, eight tools, two checks

Pydantic AI

Connects gpt-6-luna to the accounting tools over Portkey.

8 tools

Four explain the accounting, four read real figures out of SQLite.

Check 1

verify_model_id() confirms which model actually answered.

Check 2

check_grounding() traces every figure back to a tool result.

5 · Cost to run

About ten cents a month

$0.000288per chat
$0.087a month, three users
4 of 5pages use no AI at all
  • Most of the site is Python and SQL. Only the chatbot spends tokens.
  • Prompt caching. The system prompt and tool definitions are identical every call, so most input tokens come from the cache.
  • Narrow tool returns. One figure, one account, one ratio, never the whole ledger.

6 · Safety

A prompt is a request. These are guarantees.

  • Wrong figures. check_grounding() rejects any money figure that does not trace to a tool result or to the user’s own question. Ten adversarial cases, ten refusals, including a real total sitting beside an invented one.
  • The wrong model. The gateway returns HTTP 200 for a model name it does not know and quietly answers with another one, so the app reads response.model back and fails loudly.
  • Runaway cost. Per question caps on tokens, model calls and tool calls.

Still open: prompt injection is not properly tested yet.
